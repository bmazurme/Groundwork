## Предложения и обоснование

### 016 — Ручная повторная индексация и диагностика `failed`
- **Найдено:** переиндексировать можно только повторной загрузкой файла (растёт `version`, новый объект в S3); `failure_reason` показана лишь как `title` метки; у `queue.add` нет `jobId`, поэтому два клика дают два конкурентных задания.
- **Решение:** `POST /api/documents/:id/reindex` (202; 409 для `pending`/`indexing`), идемпотентность через условный `UPDATE ... RETURNING` или `jobId`, старые чанки остаются до замены; во фронтенде кнопка и раскрываемая причина ошибки.
- **Контракт:** добавляется один маршрут, существующие не меняются.

### 017 — Безопасность LLM-синтеза
- **Найдено:** `LlmProvider` ещё не написан, правила безопасности лучше зафиксировать до реализации: непрямая инъекция из недоверенных документов (авторизации нет, Issue 002), малое окно Ollama молча обрезает системную инструкцию, модель может сослаться на несуществующий источник, тексты уходят во внешний сервис и в логи.
- **Решение:** `buildPrompt` с разделителями и экранированием, бюджет контекста и `num_ctx`, `parseCitations` отбрасывает невалидные ссылки, при пустых источниках LLM не вызывается, `LOG_PROMPTS` по умолчанию выключен, враждебные документы в eval.
- **Ограничение:** полностью исключить инъекцию нельзя; это прямо указано в Issue.

### 018 — Ресурсные лимиты парсинга и `pdf-parse`
- **Найдено:** парсинг недоверенных PDF/DOCX идёт в основном процессе без таймаута и лимитов (zip-бомба, огромный текст → десятки тысяч эмбеддингов); `pdf-parse@1.1.1` не обновлялся с 2018 г.
- **Решение:** `worker_threads` с `resourceLimits` и таймаутом, `MAX_EXTRACTED_CHARS`/`MAX_CHUNKS_PER_DOCUMENT`, проверка распакованного размера DOCX, оценка замены PDF-парсера по тестовому набору и `npm audit` (замена — отдельным коммитом, не вслепую).
- **Зависимости:** новых не требуется.

### 019 — Состояние поиска в URL и история
- **Найдено:** поиск на `useMutation` — нет кеша и отмены, ответ на первый из двух быстрых запросов может перезаписать второй; перезагрузка стирает результат; ссылкой поделиться нельзя.
- **Решение:** `?q=` через `URLSearchParams` без роутера, `useQuery` с `AbortSignal`, история из 10 запросов в `localStorage`, хук `useSearchQuery`, независимый от способа получения данных (подойдёт и для SSE-стрима).
- **Контракт:** `/api` не меняется.

### 020 — Интеграционные тесты бэкенда
- **Найдено:** `test/app.e2e-spec.ts` — шаблон Nest, он запрашивает `/health` без префикса `api`, который задаётся только в `main.ts`, и не запускается в CI; CI гоняет тесты с `--passWithNoTests`; любой тест на `AppModule` тянет ONNX-модель.
- **Решение:** `configureApp(app)` общий для `main.ts` и тестов, `FakeEmbeddingsProvider`, набор `test:int` на service containers (Postgres/pgvector, Redis, MinIO) со сценарием «загрузка → indexed → поиск → удаление».
- **Зависимости:** новых нет.
