## Предложения и обоснование

### 031 — Задержка поиска
- **Найдено:** ONNX-эмбеддер работает в основном процессе вместе с HTTP и BullMQ-воркером, поэтому индексация может задерживать `/api/search` и `/api/health`; эмбеддинг запроса не кешируется; у SQL поиска нет `statement_timeout`; длина `q` не ограничена.
- **Решение:** LRU-кеш (env `QUERY_EMBEDDING_CACHE_SIZE`), замер и только затем вынос в `worker_threads` или отдельный воркер, таймаут и лимит длины запроса. Новых зависимостей нет.

### 032 — Пагинация и фильтры
- **Найдено:** `GET /documents` и `/documents/:id/chunks` без `LIMIT`; фронтенд опрашивает полный список.
- **Решение:** курсорная пагинация, фильтры, endpoint `summary` со счётчиками, индекс отдельной миграцией. Обратная совместимость: без параметров поведение прежнее; если нужна обёртка `{items, nextCursor}`, она вводится на новом пути. Это основа для виртуализированной таблицы (фича 6).

### 033 — Тесты фронтенда
- **Найдено:** есть только Cypress e2e, требующие весь Docker-стек; юнит-тестов нет, при этом есть чистая логика (`highlight-terms`, `strip-html-comments`).
- **Решение:** Vitest + Testing Library + jsdom (dev-зависимости с обоснованием и `npm audit`), запуск в первом job CI без Docker.

### 034 — Конфигурация
- **Найдено:** 16 прямых обращений к `process.env`; опечатка в `EMBEDDINGS_PROVIDER` молча выбирает ONNX; нечисловой порт даёт `NaN` после старта.
- **Решение:** модуль `config/` с проверкой при старте, одно сообщение об ошибках, тест синхронизации с `.env.example`. Значения по умолчанию не меняются.

### 035 — Объяснимость поиска
- **Найдено:** наружу отдаётся только RRF-оценка; расстояние и ранги по веткам недоступны, а порог 0.72 подобран по одному запросу (по комментарию в коде).
- **Решение:** необязательное поле `debug` по `?debug=1`, порог в env, панель деталей во фронтенде, безопасный лог без текста запроса.

## Рекомендуемый порядок
Миграции (`IMPROVEMENTS.md` п. 4) → 034 → 033 → 035 → 032 → 031. 034 и 033 дёшевы и ускоряют остальное; 035 нужен до подбора порога на eval-наборе; 031 лучше делать до стриминга ответов LLM.

## Совместимость и риски
- Публичный контракт `/api` в этом PR не меняется. При реализации 032 и 035 расширяют его только необязательными параметрами; единственное потенциально ломающее место (обёртка списка в 032) вынесено на новый путь.
- Размерность эмбеддингов, схема `document_chunks` и Dockerfile бэкенда (`node:22-slim`) не затрагиваются. Индекс из 032 добавляется отдельной миграцией.
