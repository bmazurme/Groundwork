## Предложения и обоснование

### 021 — Ключевая ветка поиска: AND-семантика
- **Найдено:** `websearch_to_tsquery` соединяет термы через `&`. Для вопроса из 4+ слов keyword-ветка почти всегда пуста, и гибридный поиск превращается в чисто векторный. Не то же, что русский словарь (`IMPROVEMENTS.md` п. 1).
- **Решение:** сначала строгий запрос; если строк меньше `KEYWORD_MIN_HITS`, ослабленный запрос с `|` (термы берутся из `tsvector_to_array(to_tsvector(...))`, без интерполяции пользовательского текста), под флагом `KEYWORD_RELAXED`. Включать по умолчанию только после проверки на eval-наборе.
- **Контракт:** `/api/search` не меняется.

### 022 — Production-развёртывание
- **Найдено:** production-стадия `apps/frontend/Dockerfile` — голый `nginx:alpine` без проксирования `/api` и SPA-фоллбэка; в production все вызовы API дадут 404. Stack-файла нет (README числит его нереализованным), пароли в compose открытым текстом, нет `healthcheck`.
- **Решение:** `nginx.conf` (шаблон с `API_UPSTREAM`, `proxy_buffering off` для будущего SSE), `docker-stack.yml` с секретами через `*_FILE`, `HEALTHCHECK` бэкенда, раздел README «Deployment».
- **Контракт:** `/api` не меняется.

### 023 — Размер бандла фронтенда
- **Найдено:** `mermaid` импортируется статически и попадает в стартовый чанк; `mermaid.initialize` вызывается на каждый блок; бюджета размера нет.
- **Решение:** ленивая загрузка `mermaid` и `DocumentViewerDialog`, `manualChunks`, скрипт проверки размера на `node:zlib` (новых зависимостей нет), измерения до/после в PR.

### 024 — Устойчивость пула Postgres
- **Найдено:** у `Pool` нет `on('error')` — по поведению `pg` ошибка на простаивающем клиенте (рестарт БД) без слушателя может завершить процесс; нет таймаутов и лимитов; `/health` использует тот же пул и зависнет при его исчерпании.
- **Решение:** обработчик ошибок, параметры из env, быстрый `/health` с метриками пула, ручная проверка `docker compose restart postgres`.
- **Контракт:** в `/api/health` добавляется необязательное поле, существующие не меняются.

### 025 — Кириллические имена файлов и `.txt`
- **Найдено (гипотеза):** `multer`/`busboy` по умолчанию читают имя файла как `latin1`, поэтому «Регламент.pdf» может сохраниться испорченным (в имени документа, дубликатах и S3-ключе); нет NFC-нормализации; `.txt` обрабатывается как Markdown.
- **Решение:** сначала воспроизвести тестом; затем `defParamCharset: 'utf8'` (если поддерживается) или `normalizeFilename`, NFC, отдельная обработка `.txt`.
- **Контракт:** меняется только при выборе нового значения `DocumentFormat` (тогда фронтенд обновляется в том же коммите).
