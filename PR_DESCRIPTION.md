# docs: анализ проекта и 5 предложений по улучшению (Issue 001–005)

## Что сделано
Исполнение: статический анализ кода `apps/backend` и `apps/frontend`, `README.md`, `IMPROVEMENTS.md`, CI и `docker-compose.yml`. Код приложения **не менялся**, приложение и тесты **не запускались** (в снимке нет `.git`, зависимости и Docker не поднимались).

1. **Открытые Issue.** В снимке нет `ISSUES.md` и `init.md`, открытых Issue в доступных материалах нет, брать в работу нечего. Если они есть в трекере, они не были переданы в этот запуск.
2. **Новые предложения** (не более 5) оформлены как тексты Issue в `docs/issues/`. Создать их в трекере из этого запуска нельзя, поэтому владельцу нужно завести их вручную (см. `docs/issues/README.md`).
3. Предложения не повторяют `IMPROVEMENTS.md` (русский FTS, eval, надёжность загрузки, миграции, реранкер/LLM). Пересечения указаны ссылками.

## Предлагаемые решения (кратко)

| Issue | Проблема | Решение |
|---|---|---|
| 001 | Чанки по 800 символов, у модели `paraphrase-multilingual-MiniLM-L12-v2` окно 128 токенов (по карточке модели): хвост чанка, вероятно, обрезается эмбеддером. `nomic-embed-text` (Ollama) даёт 768 измерений при `vector(384)`. | Размер чанка из `maxInputTokens` провайдера, проверка размерности при старте, правка комментария, документация. Переиндексация только по решению владельца. |
| 002 | Нет валидации, лимитов, helmet, авторизации; `q` без ограничения длины и может быть массивом (500). | `ValidationPipe` + DTO, throttler, helmet, опциональный `API_KEY`. |
| 003 | `/health` смотрит только Postgres; нет graceful shutdown; документы могут застрять в `pending`/`indexing`. | `/health/ready`, shutdown hooks, периодический «дозор» зависших документов. |
| 004 | Клиент теряет текст ошибок API; типы контракта дублируются; нет таймаута и отмены. | `ApiError`, таймаут/abort, пакет `packages/contract` с типами. |
| 005 | Выдача из 5 чанков может быть одним документом, чанки обрываются на стыках; пороги зашиты. | Лимит чанков на документ, необязательное поле `context`, пороги в env. |

Подробности, критерии приёмки и риски — в файлах `docs/issues/00*.md`.

## Порядок внедрения
Рекомендую: 001 (до реранкера и LLM, иначе они работают на урезанных векторах) → 004 → 003 → 002 → 005. Вместе с порядком из `IMPROVEMENTS.md` (миграции → eval → …) измерять эффект 001 и 005 нужно на eval-наборе.

## Совместимость и риски
- Публичный контракт `/api` не меняется. Issue 002 добавляет коды ошибок 400/401/429, Issue 005 — необязательное поле `context`.
- Новые зависимости предлагаются только в Issue 002 (`class-validator`, `class-transformer`, `@nestjs/throttler`, `helmet`) с обоснованием. `npm audit` обязателен перед добавлением.
- Dockerfile остаётся на `node:22-slim`. Размерность эмбеддингов не меняется ни в одном предложении.

## Допущения и ограничения
- Утверждение о лимите 128 токенов взято из карточки модели и не проверялось запуском. Первый шаг Issue 001 — измерить длину в токенах реальных чанков и подтвердить обрезку.
- Анализ статический: ошибки вроде 500 при `q` массивом выведены из кода (`query.trim()` на не-строке), на запущенном стеке не воспроизводились.
- Эти файлы — только документация, поэтому проверок lint/build/test для них нет.
