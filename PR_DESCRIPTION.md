# docs: второй раунд анализа — 5 новых предложений (Issue 006–010)

## Что сделано
Статический анализ `apps/backend`, `apps/frontend`, `README.md`, CI и `docker-compose.yml`. Код приложения **не менялся**; приложение, тесты и Docker не запускались (в снимке нет `.git`, зависимости не ставились). Единственная проверка запуском: регулярное выражение из `unglueColumns` и обработка HTML-сущностей прогнаны в `node -e` (см. Issue 006).

1. **Открытые Issue.** В снимке нет `ISSUES.md`, `init.md` и данных трекера, поэтому открытых Issue для работы нет. В репозитории уже есть предложения первого раунда (`IMPROVEMENTS.md`, Issue 001–005); они не дублируются, задачи из них не реализовывались: это задание про анализ и предложения.
2. **Новые предложения** (5, не больше) оформлены как тексты Issue в `docs/issues/006…010-*.md`, индекс обновлён в `docs/issues/README.md`.
3. **Почему не созданы в трекере.** Из этого запуска можно опубликовать только файлы одним PR и не более одного Issue через `.lab/issue.json`, причём только без других изменений. Пять Issue так не создать, поэтому тексты лежат в `docs/issues/`; владельцу достаточно завести Issue из них (заголовок и тело берутся как есть).

## Совместимость и риски
- Публичный контракт `/api` в этом PR не меняется. Предложения расширяют его только обратно совместимо: необязательные поля (007), необязательные параметры (009), новые коды ответа 200/409 при загрузке (008, описать при реализации, фронтенд обновить в том же коммите).
- Новые зависимости: возможно `he` (006, декодирование сущностей; можно обойтись ручной таблицей). Остальное — без зависимостей. `npm audit` обязателен перед добавлением.
- Размерность эмбеддингов и схема `document_chunks` в части вектора не затрагиваются; Dockerfile бэкенда остаётся на `node:22-slim`.

## Допущения и ограничения
- Анализ статический. Утверждения про порчу `2FA` и про необработанные сущности подтверждены только прогоном самих выражений в Node, не на стеке.
- Неизвестно, как часто такие строки встречаются в реальных корпусах владельца: первый шаг Issue 006 — найти их в уже проиндексированных чанках.
- Пункты про pgvector `hnsw.iterative_scan` (009) требуют pgvector ≥ 0.8; версия в образе `pgvector/pgvector:pg16` не проверялась.
- Изменения `.github/workflows/` в этот PR не входят и публикуются вручную (Issue 010 — только текст предложения).
- Проверок lint/build/test для документации нет.
