# Issue 023: Mermaid и Markdown-рендер попадают в основной бандл фронтенда, нет бюджета размера

**Метки:** frontend, performance

## Проблема
- `MermaidDiagram.tsx` делает статический `import mermaid from 'mermaid'`, а `MarkdownContent` импортируется из `SearchPanel` и `DocumentViewerDialog`, которые подключены в `App.tsx` статически. В результате `mermaid` (несколько сотен КБ в gzip вместе с зависимостями) и `react-markdown` входят в стартовый чанк, хотя нужны только после первого поиска или открытия документа, и только если в тексте есть ```` ```mermaid ````-блок.
- `vite.config.ts` не задаёт ни `manualChunks`, ни `build.chunkSizeWarningLimit`, в CI нет проверки размера. Рост бандла со временем (Gravity UI, будущая страница аналитики, виртуализация из ТЗ) никто не заметит.
- `mermaid.initialize(...)` вызывается в каждом `useEffect` каждого диаграммного блока при каждой смене темы: при 10 диаграммах это 10 инициализаций.

## Предложение
- `MermaidDiagram` загружать лениво: `const mermaid = (await import('mermaid')).default` внутри эффекта (одно разделяемое обещание на модуль, чтобы `initialize` вызывался один раз на тему, а не на блок). Пока модуль грузится, показывать текущий `null`/скелетон фиксированной высоты, чтобы не прыгал layout.
- `DocumentViewerDialog` подключать через `React.lazy` + `Suspense` (диалог не нужен до клика).
- `vite.config.ts`: `build.rollupOptions.output.manualChunks` для `react`/`react-dom`, `@gravity-ui/*`, `mermaid` (последний и так станет отдельным динамическим чанком); `build.chunkSizeWarningLimit` выставить по факту после измерения.
- Скрипт `npm run size -w frontend`: после `vite build` читает `dist/assets/*.js`, считает gzip-размер входного чанка и падает, если он больше порога в `apps/frontend/size-budget.json`. Новых зависимостей не нужно (`node:zlib`). Шаг в CI описывается текстом, его добавляет владелец.
- Перед изменениями зафиксировать текущие размеры (`vite build` выводит таблицу) и приложить до/после в PR.

## Критерии приёмки
- Размер входного чанка (gzip) уменьшается; точная цифра фиксируется в PR, ориентир: убрать `mermaid` из стартового чанка полностью.
- Страница без поиска не запрашивает чанк `mermaid` (проверить во вкладке Network или проверкой Cypress `cy.intercept` на файл чанка).
- Документ с mermaid-диаграммой по-прежнему рисуется, при ошибке парсинга остаётся fallback из `<pre>`; смена темы перерисовывает диаграмму (ручная проверка и существующий `upload-search.cy.ts`).
- `npm run build` и `npm run lint` зелёные.

## Контракт
`/api` не меняется. Только фронтенд.

## Связь
Issue 019 (состояние поиска) и будущая страница аналитики (`README`, «Current state»): бюджет размера защищает их от неконтролируемого роста.
