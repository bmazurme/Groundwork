# Issue 033: Юнит- и компонентные тесты фронтенда

**Метки:** testing, frontend, ci

## Проблема
У фронтенда есть только Cypress e2e (`apps/frontend/cypress`), которые в CI требуют поднятого полного стека (`docker compose up --build`, загрузка модели эмбеддингов). В `apps/frontend/src` нет ни одного юнит-теста, хотя в нём есть чистая логика: `highlight-terms.ts`, `strip-html-comments.ts`, обработка ошибок и формирование запросов в `api/client.ts`, выбор интервала опроса в `App.tsx`. Регрессии в подсветке терминов или очистке HTML-комментариев (последняя влияет на безопасность отображаемого Markdown) обнаруживаются только вручную или в долгом e2e.

## Предложение
1. **Vitest** (уже используется Vite, общий конфиг, без отдельного транспайлера) + **@testing-library/react** + **jsdom** как dev-зависимости. Для каждой указать причину в PR и выполнить `npm audit` до и после.
2. Тесты чистых функций: `highlight-terms` (регистр, кириллица, спецсимволы regex в запросе, пересекающиеся термины, пустой запрос), `strip-html-comments` (вложенные и незакрытые комментарии).
3. Компонентные тесты `SearchPanel` и `DocumentsTable` с замоканным `fetch`: пустое состояние, загрузка, ошибка, результат с несколькими источниками, статус `failed` с причиной.
4. Скрипт `npm run test -w frontend`, включение в корневой `npm run test` и в первый job CI (`build`), который не поднимает Docker. Одновременно убрать `--passWithNoTests` (см. `IMPROVEMENTS.md` п. 2).
5. Порог покрытия не ставить сразу; зафиксировать базовое значение в PR и поднимать постепенно.

## Критерии приёмки
- `npm run test` запускает тесты обоих приложений и падает при сломанной подсветке (проверить намеренной поломкой в черновом коммите).
- Время выполнения frontend-тестов в CI меньше минуты, Docker не нужен.
- Cypress остаётся только для сквозных сценариев.
