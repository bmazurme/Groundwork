# Issue 035: Кеш эмбеддингов запросов и бюджет времени поиска

**Метки:** backend, performance, reliability

## Проблема
`SearchService.query()` на каждый запрос заново считает эмбеддинг (`this.embeddings.embed(trimmed)`), затем ждёт `Promise.all` двух SQL-запросов. Что не защищено:
- Провайдер ONNX работает в процессе API: каждое вычисление занимает CPU и блокирует event loop, повторные одинаковые запросы (повторное нажатие, запрос из истории, eval-прогон, перезагрузка страницы) платят полную цену.
- Планируемый стриминг ответа повторит поиск при повторной отправке; планируемый реранкер удвоит стоимость каждого запроса.
- Нет верхней границы времени: зависший Ollama или медленный запрос к Postgres держит HTTP-соединение бесконечно (по умолчанию у `fetch`/`pg` нет таймаута запроса); нет ограничения длины запроса, поэтому очень длинная строка уходит в эмбеддер целиком.
- Параллельные запросы не ограничены: десять одновременных поисков ставят десять эмбеддингов в очередь одного воркера.

## Предложение
1. LRU-кеш `normalizedQuery -> vector` внутри обёртки `CachingEmbeddingsProvider`, реализующей тот же интерфейс `EmbeddingsProvider` (декоратор, подключается в `embeddings.module.ts`). Ключ включает идентификатор провайдера/модели (связь с Issue 014), чтобы смена модели не отдавала чужие векторы. Размер и TTL — env (`EMBEDDINGS_QUERY_CACHE_SIZE`, `0` отключает; по умолчанию поведение без изменений). Применять только к запросам поиска, не к индексации документов.
2. Нормализация ключа: `trim`, схлопывание пробелов, Unicode NFKC; регистр не менять без проверки, что модель к нему нечувствительна.
3. Лимит длины запроса (например 1 000 символов) с ответом 400; тайм-аут стадий поиска (`SEARCH_TIMEOUT_MS`, `AbortSignal` для Ollama, `statement_timeout` на запрос поиска через `SET LOCAL`) и ответ 503/504 с понятным сообщением вместо зависания.
4. Ограничение параллелизма эмбеддингов запросов (небольшой семафор) с очередью и отказом при переполнении.
5. Метрики попаданий в кеш (счётчики в логе до появления Issue 012).

## Критерии приёмки
- Юнит-тесты: повторный запрос не вызывает провайдер второй раз; разные нормализованные формы одного запроса попадают в один ключ; вытеснение по размеру; кеш выключен при размере 0; ошибка провайдера не кешируется.
- Тест тайм-аута с фейковым медленным провайдером: ответ в пределах бюджета, без утечки висящих запросов.
- Замер до/после на одном запросе в README PR (холодный и тёплый путь).
- Результаты поиска и контракт `/api/search` не меняются.
