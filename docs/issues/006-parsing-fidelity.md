# Issue 006: Парсеры портят текст (склейка «2FA» → «2 FA», HTML-сущности) и молча принимают пустые PDF

**Метки:** ingestion, search-quality, bug

## Проблема
Найдено чтением `documents/parsing/parse-document.ts`; воспроизведено только само регулярное выражение в Node (проверка запуском через `node -e`), на стеке целиком не проверялось.
1. `unglueColumns` заменяет `([0-9])([A-ZА-ЯЁ])` на `$1 $2` для **всего** текста PDF. Результат: `2FA` → `2 FA`, `5G` → `5 G`, `4K` → `4 K`, `ISO 27001A` → `ISO 27001 A`, `v2.0Beta` → `v2.0 Beta`. Идентификаторы, версии и аббревиатуры в технических документах искажаются и перестают находиться keyword-веткой (в запросе `2FA`, в чанке `2 FA`).
2. `stripHtml` не декодирует сущности: `&amp;`, `&nbsp;`, `&lt;`, `&#1099;` остаются в тексте и попадают в эмбеддинги и в выдачу. Заголовки и абзацы схлопываются в одну строку (`\s+` → пробел), поэтому структурный чанкер не видит границ абзацев и режет только по предложениям.
3. DOCX: `mammoth.extractRawText` теряет заголовки и списки. Есть `convertToMarkdown`-подобный путь (через HTML), но он не используется.
4. Скан-PDF без текстового слоя даёт пустую строку; ошибка «No extractable text found in document» не объясняет причину (возможно, нужен OCR).

## Предложение
- `unglueColumns` применять только к строкам, похожим на таблицу (например, строки, где такая склейка встречается ≥2 раза или рядом есть другие признаки табличной строки), либо ограничить правило случаем «цифра + заглавная + строчная кириллица/латиница» (`27001Перевод`), не трогая `2FA`/`5G`. Набор регрессионных примеров вынести в тест.
- Для HTML: декодировать сущности (`he` — маленькая зависимость, либо обработка нескольких основных сущностей вручную) и заменять блочные теги (`p`, `div`, `li`, `h1–h6`, `br`, `tr`) переводом строки до удаления остальных тегов.
- Для DOCX: пробовать `mammoth.convertToHtml` + тот же HTML-путь, чтобы сохранить заголовки и списки (сначала сравнить на реальных документах).
- Пустой результат PDF: понятная причина в `failure_reason` («в PDF нет текстового слоя, возможно, это скан»).

## Критерии приёмки
- Юнит-тесты `parse-document`: `2FA`, `5G`, `v2.0Beta` не меняются; пример склеенной таблицы из комментария разделяется.
- HTML-тест: `&amp;`, `&nbsp;`, числовые сущности декодируются, абзацы остаются раздельными строками.
- Для пустого PDF `failure_reason` содержит понятное объяснение.
- Если добавляется зависимость (`he`), указать причину и приложить `npm audit`.

## Риски
Изменение парсинга меняет содержимое чанков: уже проиндексированные документы останутся со старым текстом, пока владелец не запустит переиндексацию (автоматически не переиндексировать). Связано с Issue 001 (размер чанка) и `IMPROVEMENTS.md` п. 2 (eval).
