# Issue 015: Доступ к оригиналу документа: скачивание и просмотр PDF/DOCX

**Метки:** feature, frontend, backend

## Проблема
Исходный файл хранится в S3, но получить его нельзя: API отдаёт только текст чанков (`GET /documents/:id/chunks`), а `DocumentViewerDialog` показывает именно чанки. Для PDF и DOCX пользователь, увидев цитату, не может открыть оригинал, чтобы проверить контекст, таблицы и рисунки, потерянные при извлечении текста. Для индексации с ошибкой (`failed`) скачать проблемный файл, чтобы разобраться, тоже нельзя.

## Предложение
- `GET /api/documents/:id/file`: стримит объект из S3 (`StorageService.download` уже есть; добавить потоковый вариант, чтобы не держать файл в памяти), заголовки `Content-Type` по формату, `Content-Disposition: attachment; filename*=UTF-8''…` (кодирование кириллицы по RFC 5987); `?inline=1` только для `pdf`.
- Для `html` отдавать только как `attachment` и с `Content-Security-Policy: sandbox`, `X-Content-Type-Options: nosniff`, чтобы загруженный HTML не исполнялся в origin приложения.
- Фронтенд: кнопка «Скачать оригинал» в `DocumentsTable` и в `DocumentViewerDialog`; для PDF — ссылка «Открыть на странице» (номер страницы появится после Issue 007).
- Новый маршрут добавляется обратно совместимо, существующие не меняются; тип в `api/types.ts`.

## Критерии приёмки
- Юнит/интеграционный тест: скачанные байты совпадают с загруженными, имя с кириллицей отдаётся корректно, для HTML выставлены защитные заголовки, неизвестный `id` даёт 404, не-UUID — 400.
- Ручной сценарий: загрузить PDF с русским именем → скачать → хеш совпадает.

## Риски
Безопасность: HTML/SVG-содержимое от пользователей — главный риск (отсюда sandbox и `attachment`); доступ к файлам должен защищаться тем же API-ключом, что остальные маршруты (Issue 002).

## Связь
