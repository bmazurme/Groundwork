# Issue 014: Учёт версии модели эмбеддингов: защита от смешивания несовместимых векторов

**Метки:** data-integrity, search

## Проблема
В `local-onnx-embeddings.provider.ts` комментарий прямо говорит: при смене модели «векторы двух моделей несравнимы», нужна переиндексация. Но система нигде не хранит, **какой моделью** посчитан вектор. Если поменять `EMBEDDINGS_PROVIDER` (onnx ↔ ollama) или имя модели при той же размерности, то:
- старые чанки останутся в индексе, а запрос будет эмбеддиться новой моделью — поиск тихо деградирует, ошибок нет;
- при другой размерности запросы будут падать с ошибкой Postgres, понятной только по логам;
- нет списка документов, которые нужно переиндексировать.

Размерность `vector(384)` — единая точка связи с `document_chunks`, поэтому нужна явная проверка, а не догадка.

## Предложение
- Интерфейс `EmbeddingsProvider` получает `readonly modelId: string` (например `onnx:Xenova/paraphrase-multilingual-MiniLM-L12-v2`) и `dimensions`.
- Колонка `documents.embedding_model TEXT` (после миграций, `IMPROVEMENTS.md` п. 4), заполняется в конце успешной индексации.
- При старте: если размерность провайдера ≠ `EMBEDDING_DIMENSIONS` — падать с понятным сообщением (это согласуется с Issue 001). Если есть документы с `embedding_model` ≠ текущей — предупреждение в лог и поле в `/api/health` (необязательное: `staleEmbeddings: number`).
- Поиск фильтрует по `d.embedding_model = текущая` в векторной ветке (иначе несравнимые векторы попадают в выдачу); keyword-ветка не затрагивается.
- Команда `npm run reindex -- --stale` ставит такие документы в очередь заново. Сама смена модели и пересчёт данных остаются решением владельца: скрипт по умолчанию печатает список (dry-run).

## Критерии приёмки
- Юнит-тесты: определение устаревших документов, фильтр векторной ветки, ошибка при несовпадении размерности.
- Ручной сценарий: проиндексировать документ, сменить `modelId` → `/health` показывает `staleEmbeddings: 1`, поиск не возвращает его семантически, после `reindex` возвращает.

## Риски
Для существующих строк `embedding_model` пуст: миграция должна проставить текущую модель (допущение: до сих пор использовалась модель по умолчанию; владельцу подтвердить), иначе всё будет считаться устаревшим.

## Связь
Зависит от миграций; дополняет Issue 001 (проверка размерности) и 008 (повторная индексация).
