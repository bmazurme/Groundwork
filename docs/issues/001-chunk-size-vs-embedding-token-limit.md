# Issue 001: Чанки длиннее лимита токенов эмбеддера; смена провайдера ломает размерность

**Метки:** search-quality, embeddings, bug-risk

## Проблема
1. `chunk-text.ts` режет текст по символам (`CHUNK_SIZE = 800`, `CHUNK_OVERLAP = 150`). Модель `Xenova/paraphrase-multilingual-MiniLM-L12-v2` (`local-onnx-embeddings.provider.ts`) по карточке модели имеет `max_seq_length = 128` токенов. 800 символов — это примерно 200–250 токенов для английского и больше для русского. Токенайзер, по всей видимости, молча обрезает вход. Тогда вектор описывает только начало чанка, а хвост чанка невидим для семантического поиска. Это нужно подтвердить измерением (см. ниже), в этом анализе оно не запускалось.
2. `EMBEDDING_DIMENSIONS = 384` стоит константой, а комментарий в `embeddings.constants.ts` называет другую модель (`all-MiniLM-L6-v2`). У `OllamaEmbeddingsProvider` модель по умолчанию `nomic-embed-text` выдаёт 768 измерений. При `EMBEDDINGS_PROVIDER=ollama` вставка в `vector(384)` падает уже в процессоре, и каждый документ получает `failed` с малопонятной ошибкой Postgres.

## Предложение
- Считать размер чанка в токенах токенайзера активного провайдера (или хотя бы взять консервативный лимит в символах, выведенный из токенов). Добавить в `EmbeddingsProvider` поля `dimensions` и `maxInputTokens`. Размер чанка выводить из них, а не хранить отдельной константой.
- На старте приложения (после warm-up) делать пробный `embed('test')` и сверять длину вектора с `EMBEDDING_DIMENSIONS`. При несовпадении падать с понятным сообщением. Без изменения схемы и без смены модели.
- Обновить устаревший комментарий. Задокументировать в README, что для Ollama нужна модель на 384 измерения либо миграция схемы.
- Смена размера чанка потребует переиндексации. Это отдельное решение владельца, автоматически ничего не переиндексировать.

## Критерии приёмки
- Юнит-тест: ни один чанк не превышает `maxInputTokens` (на RU и EN текстах).
- Старт с провайдером неподходящей размерности завершается явной ошибкой.
- Замер до и после на eval-наборе (см. `IMPROVEMENTS.md`, п. 2) показывает не худший recall@5.

## Риски
Меняется разбиение, а значит и содержимое индекса. Нужна ручная переиндексация. Связано с `IMPROVEMENTS.md` п. 4 (миграции).
