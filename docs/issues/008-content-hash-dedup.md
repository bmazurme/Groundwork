# Issue 008: Идентичные файлы переиндексируются и дублируются; нет хеша содержимого

**Метки:** ingestion, cost, data-quality

## Проблема
В `documents.service.ts` документ идентифицируется только по имени файла. Следствия:
- Повторная загрузка **того же самого** файла под тем же именем увеличивает `version`, заново загружает объект в S3 и запускает полную переиндексацию (парсинг, эмбеддинги всех чанков), хотя содержимое не изменилось. Для локального ONNX это минуты CPU, для платного эмбеддера — деньги.
- Один и тот же файл под двумя именами (`policy.pdf`, `policy (1).pdf`) создаёт два документа с одинаковыми чанками. В выдаче поиска (топ-5) такие дубликаты занимают сразу несколько мест.
- Нет способа понять, изменился ли файл между версиями.

## Предложение
- Миграция: колонка `documents.content_sha256 TEXT` (nullable для старых строк) и индекс по ней.
- При загрузке считать SHA-256 буфера (`node:crypto`, без новых зависимостей).
  - Совпадает хеш с существующим документом того же имени и статус `indexed` → ничего не загружать и не ставить в очередь, вернуть существующую запись (HTTP 200).
  - Совпадает хеш с документом **с другим именем** → вернуть 409 с идентификатором существующего документа (или принять с флагом `duplicateOf`; выбор поведения — решение владельца, по умолчанию 409).
- Поле `contentSha256` не добавлять в публичный контракт сразу; при необходимости — отдельным необязательным полем.
- Для старых документов хеш можно досчитать фоновой задачей из S3 (опционально).

## Критерии приёмки
- Тест: повторная загрузка идентичного файла не создаёт задачу в очереди и не меняет `version`; загрузка изменённого файла создаёт новую версию.
- Тест: загрузка того же содержимого под другим именем даёт 409.
- Фронтенд показывает понятное сообщение при 409 (учесть Issue 004 — `ApiError`).

## Риски
Меняется семантика `POST /api/documents` (новые коды 200/409), поэтому изменение описывается в PR и фронтенд обновляется в том же коммите. Нужна миграция (`IMPROVEMENTS.md` п. 4). Гонка двух параллельных загрузок решается уникальным индексом по имени из `IMPROVEMENTS.md` п. 3.
