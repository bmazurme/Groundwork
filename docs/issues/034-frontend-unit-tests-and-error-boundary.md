# Issue 034: Юнит-тесты фронтенда и обработка падений рендера

**Метки:** frontend, testing, reliability

## Проблема
- Во фронтенде есть только Cypress e2e (`cypress/e2e/*.cy.ts`) и нет юнит-тестов, хотя есть чистая логика: `components/highlight-terms.ts`, `components/strip-html-comments.ts`, разбор ответов в `api/client.ts`. Эти функции работают с произвольным пользовательским текстом (регулярные выражения, HTML-комментарии) и легко ломаются на краевых случаях: спецсимволы regex в запросе, кириллица, пустые термины, вложенные комментарии.
- Нет `ErrorBoundary`: исключение при рендере Markdown/Mermaid (`MarkdownContent`, `MermaidDiagram`) в произвольном документе размонтирует всё дерево — белый экран вместо сообщения. Документы пользовательские, значит входные данные недоверенные.
- e2e-тесты тяжёлые (нужен весь стек), поэтому на них нельзя положиться для быстрой обратной связи на каждый PR.

## Предложение
1. Vitest + `@testing-library/react` + `jsdom` как dev-зависимости (Vitest нативно работает с Vite-конфигом проекта; обоснование и `npm audit` — в PR). Скрипт `npm run test -w frontend`, подключение к корневому `npm run test` и CI.
2. Тесты чистых функций: `highlight-terms` (regex-спецсимволы `.*+?()[]`, регистр, кириллица, перекрывающиеся термины), `strip-html-comments` (незакрытый комментарий, несколько подряд), клиент API (ошибка сервера, не-JSON ответ, сетевая ошибка — связь с Issue 004).
3. Компонентные тесты на пустые состояния и состояния загрузки/ошибки `DocumentsTable` и `SearchPanel` с замоканным `fetch`.
4. `ErrorBoundary` вокруг `MarkdownContent`/`MermaidDiagram` и корня приложения: показывает понятное сообщение и кнопку «Повторить», ошибку отправляет в `console.error` (позже в наблюдаемость). Тест: компонент, бросающий исключение, не ломает соседние.

## Критерии приёмки
- `npm run test` запускает и бэкенд, и фронтенд юнит-тесты, CI зелёный без `--passWithNoTests`.
- Документ с некорректным Mermaid-блоком отображается с сообщением об ошибке блока, остальной текст и интерфейс работают (проверено вручную и тестом).
- Покрытие перечисленных функций включает минимум по 3 краевых случая на функцию.
