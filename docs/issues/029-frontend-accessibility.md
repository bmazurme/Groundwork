# Issue 029: Доступность интерфейса (a11y): живые области, клавиатура, подписи

**Метки:** frontend, a11y

## Проблема
Анализ статический (`App.tsx`, `SearchPanel.tsx`, `DocumentsTable.tsx`, `UploadDropzone.tsx`, `index.html`); проверок скринридером и автоматического аудита не проводилось. По коду видно:
- В `src` всего три упоминания `aria`/`role` (одно из них — `role="button"` у dropzone). Результат поиска (`searchMutation.data.answer`, список источников) появляется без `aria-live`, поэтому пользователь скринридера не узнаёт, что ответ пришёл. Когда в Issue «LLM-синтез» будет добавлен стриминг, это станет заметнее: текст будет меняться постоянно.
- Статусы документов (`pending`, `indexing`, `indexed`, `failed`) в таблице обновляются опросом каждые 2 секунды. Пульсирующая точка помечена `aria-hidden`, но другого текстового эквивалента смены статуса нет.
- Поле поиска и кнопки без явных `aria-label` там, где текст кнопки иконка-only (удаление, просмотр) — нужно проверить по `DocumentsTable.tsx`.
- Dropzone: `role="button"` на `div` с вложенным скрытым `input`, при этом состояние `disabled` передаётся только через `tabIndex` и `data-disabled`, а не `aria-disabled`.
- `<html lang="en">` жёстко, хотя продукт RU+EN, а интерфейс сейчас английский. Если локализация (RU) появится, `lang` нужно переключать вместе с языком.
- Цвета статусов и выделение найденных терминов (`highlight-terms.ts`) могут опираться только на цвет; контраст не проверялся ни в светлой, ни в тёмной теме.

## Предложение
1. Регион результатов поиска: `role="status"` (или `aria-live="polite"`) для краткого сообщения «Найдено N фрагментов» / «Ничего не найдено»; сам длинный ответ не озвучивать целиком при каждом обновлении потока (`aria-busy` на время стриминга, один объявленный итог).
2. Статус в таблице — текст для скринридера (`<span class="sr-only">`) и объявление смены статуса через общий живой регион, но только при переходе в `indexed`/`failed` (не на каждый опрос).
3. Иконочные кнопки получают `aria-label` и `title`; dropzone — `aria-disabled`, `aria-describedby` на подпись с допустимыми форматами.
4. Автоматическая проверка: `cypress-axe` (dev-зависимость, причина: единственный воспроизводимый способ ловить регрессии a11y в CI; проверить `npm audit`, лицензия MIT) на главной странице и после поиска, порог: ноль нарушений уровня `serious`/`critical`.
5. Выделение терминов — через `<mark>`, а не только цвет; проверить контраст в обеих темах (минимум 4.5:1 для обычного текста).
6. Если появится локализация, `document.documentElement.lang` должен меняться вместе с ней; сейчас — оставить `en` и зафиксировать это в README.

## Критерии приёмки
- Скриншот/запись проверки с клавиатуры: можно загрузить файл, выполнить поиск, открыть источник и удалить документ без мыши, фокус виден и не теряется после закрытия диалогов.
- `cypress-axe` на двух страницах без нарушений `serious`/`critical`; список исключений, если они нужны, с обоснованием в коде.
- Ручная проверка скринридером (NVDA или VoiceOver): результат поиска и смена статуса объявляются один раз.
- Контракт `/api` не меняется.
