# Issue 032: Пагинация и лимиты для `GET /documents` и `GET /documents/:id/chunks`

**Метки:** backend, frontend, api, performance

## Проблема
`DocumentsService.findAll()` возвращает все документы, `getChunks()` — все чанки документа, без `LIMIT`. Фронтенд (`DocumentsTable`, `DocumentViewerDialog`) рисует всё сразу.
- Документ на 500 страниц даёт тысячи чанков в одном JSON-ответе и в одном рендере диалога.
- Список документов растёт неограниченно; запрос и таблица деградируют линейно. Виртуализированная таблица из плана (UX-пункт 6) решает только рендер, но не объём ответа.
- Нет сортировки и фильтра на стороне сервера, поэтому клиентские фильтры будут работать только по загруженной части.
- `:id` не проверяется как UUID: невалидная строка доходит до Postgres и даёт 500 вместо 400/404 (пересекается с 002, но здесь это часть контракта списков).

## Предложение
Обратно совместимо (контракт меняется аддитивно):
1. Query-параметры `limit` (по умолчанию 100, максимум 500), `cursor` (keyset по `(created_at, id)`, не `OFFSET`), `status`, `format`, `q` (подстрока имени, `ILIKE` с экранированием `%`/`_`), `sort=created_at|name`.
2. Ответ остаётся массивом, когда параметры не переданы; курсор следующей страницы отдаётся в заголовке `X-Next-Cursor` (или `Link`). Так существующий клиент не ломается. Альтернатива — обёртка `{items, nextCursor}` с версионированием; решение зафиксировать в PR.
3. Для `/chunks`: `limit`/`afterIndex` по `chunk_index`, индекс `(document_id, chunk_index)` уже полезен для этого запроса (общее с Issue 026).
4. Фронтенд: `useInfiniteQuery` (TanStack Query) для таблицы и диалога, «Загрузить ещё» либо подгрузка при прокрутке; серверные фильтры вместо клиентских.
5. Валидация `:id` через `ParseUUIDPipe`.

## Критерии приёмки
- Юнит/интеграционные тесты: корректность курсора при одинаковых `created_at`, пустой результат, `limit` выше максимума отклоняется или обрезается (поведение описано), спецсимволы в `q`.
- Вручную: 1 000 загруженных фиктивных документов — первая страница отвечает быстро, размер ответа ограничен.
- Запрос без параметров возвращает прежний формат (до лимита по умолчанию; при превышении явный заголовок продолжения).
- Cypress-сценарии загрузки/поиска остаются зелёными.
