# Issue 032: Пагинация и серверная фильтрация списков документов и чанков

**Метки:** api, backend, frontend, scalability

## Проблема
- `GET /api/documents` (`DocumentsService.findAll`) возвращает все строки таблицы одним ответом без `LIMIT`; фронтенд опрашивает этот endpoint каждые несколько секунд (`refetchInterval` в `App.tsx`), пока есть документы в обработке. На тысячах документов каждый опрос передаёт и сериализует весь список.
- `GET /api/documents/:id/chunks` отдаёт все чанки документа сразу; для большого файла это сотни записей с полным текстом, хотя диалог просмотра показывает их постранично глазами.
- Виртуализированная таблица из спецификации продукта (фича 6) без серверных фильтров и пагинации решает только половину проблемы: отрисовка быстрая, а передача данных остаётся полной.

## Предложение
Обратно совместимое расширение контракта:
1. `GET /api/documents?limit=&cursor=&status=&format=&q=`: курсорная пагинация по `(created_at, id)`, фильтры по статусу, формату и подстроке имени (`ILIKE` с экранированием). Без параметров поведение прежнее, но с верхним пределом `limit` (по умолчанию 200) и заголовком `X-Total-Count` либо полем в обёртке, выбрать один вариант и записать в README. Если выбрана обёртка `{items, nextCursor}`, это ломающее изменение: тогда новый путь `/api/documents/page`, а старый остаётся до обновления фронтенда в том же PR.
2. `GET /api/documents/summary`: счётчики по статусам одним запросом `GROUP BY status`. Опрос во фронтенде заменяется на лёгкий summary + запрос страницы только при смене счётчиков.
3. `GET /api/documents/:id/chunks?limit=&offset=` с значениями по умолчанию, не меняющими поведение для малых документов.
4. Индекс `documents (created_at DESC, id DESC)` отдельной миграцией (после `IMPROVEMENTS.md` п. 4).
5. Фронтенд: `useInfiniteQuery` (TanStack Query) + существующая таблица; фильтры отправляются на сервер.

## Критерии приёмки
- Интеграционный тест (Issue 020): 250 документов, страницы по 100 возвращаются без пропусков и повторов, фильтры комбинируются.
- Невалидный `cursor`/`limit` даёт 400, а не 500.
- Опрос во время индексации не загружает полный список (проверить во вкладке Network / Cypress intercept).
