# Issue 028: Загрузка: несколько файлов, клиентская проверка и прогресс

**Метки:** frontend, ux

## Проблема
Найдено чтением `UploadDropzone.tsx`, `App.tsx`, `api/client.ts`:
- `handleFiles` берёт только `files?.[0]`. Если перетащить несколько файлов, остальные молча игнорируются, без сообщения. Input без `multiple`.
- Атрибут `accept` ограничивает только диалог выбора. При перетаскивании файла любого типа проверка не выполняется, и пользователь узнаёт об ошибке только после отправки (ответ 400 превращается в общее сообщение «Upload ... failed with status 400», серверный текст теряется — это отдельный пункт Issue 004).
- Нет клиентского предела размера. Большой файл целиком уходит на сервер, а `multer` с `memoryStorage()` держит его в памяти (серверный лимит — Issue 002 и 018). Пользователь не видит ни размера, ни прогресса, только спиннер и «Uploading…».
- Подпись «PDF, DOCX, HTML, or Markdown» не упоминает `.txt`, хотя он принимается.
- Одна мутация `uploadMutation` на всю страницу: пока идёт загрузка, `disabled` блокирует весь dropzone.

## Предложение
1. Разрешить `multiple`. Валидация на клиенте единой функцией `validateUpload(file)` в `components/upload-validation.ts`: расширение из того же списка, что на сервере (`formatFromFilename` — вынести общий список в `api/types.ts`, см. Issue 004), максимальный размер из `VITE_MAX_UPLOAD_MB` (по умолчанию тот же, что на сервере), непустой файл.
2. Очередь загрузок на клиенте: файлы отправляются последовательно (по одному запросу, чтобы не перегружать индексацию), у каждого свой статус `queued | uploading | done | error` и сообщение об ошибке. Для списка использовать существующие компоненты Gravity UI; новых зависимостей нет.
3. Прогресс отправки: `fetch` не даёт `upload progress`, поэтому либо `XMLHttpRequest` для загрузки (только в `api/client.ts`), либо без процентов, но с размером и именем файла. Выбрать второе, если усложнение не оправдано; решение описать в PR.
4. Отклонённые файлы показывать списком с причиной («тип не поддерживается», «больше N МБ»), а не одним общим тостом.
5. Исправить подпись форматов и вынести её из того же списка расширений.

## Критерии приёмки
- Cypress-сценарий: загрузка трёх файлов (два допустимых и один `.exe`) приводит к двум документам в таблице и одному сообщению об отклонении с названием файла и причиной.
- Юнит-тесты `validateUpload` (расширение в разном регистре, пустой файл, предел размера на границе).
- Один неудачный файл не прерывает остальные в очереди.
- Серверный контракт `/api/documents` не меняется (по-прежнему один файл в запросе).
