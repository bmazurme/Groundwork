# Issue 034: Типизированная конфигурация с проверкой при старте

**Метки:** reliability, backend, dx

## Проблема
Конфигурация читается напрямую через `process.env` в 16 местах `apps/backend/src` (`main.ts`, провайдеры эмбеддингов, хранилище, очередь, база), у каждого места свои значения по умолчанию и своё приведение типов. Последствия:
- Опечатка в значении (`EMBEDDINGS_PROVIDER=ollamaa`) молча выбирает ONNX: фабрика в `embeddings.module.ts` проверяет только `=== 'ollama'`.
- `REDIS_PORT=abc` превращается в `NaN` и ломает подключение уже после старта, с неочевидной ошибкой.
- Отсутствует единый список переменных: `.env.example` и README приходится синхронизировать вручную, и они расходятся.
- Планируемые фичи (`RERANKER_PROVIDER`, `LLM_PROVIDER`, ключи Langfuse, лимиты загрузки из Issue 002/018, таймауты из Issue 031) добавят ещё десятки переменных.

## Предложение
1. Один модуль `config/` со схемой переменных и функцией `loadConfig(env)`, возвращающей типизированный объект. Для схемы взять `zod` (если нужна новая зависимость: обосновать, проверить `npm audit`) либо написать минимальный валидатор без зависимостей, если набор типов ограничен строками, числами и enum-ами.
2. Приложение при старте падает с одним сообщением, перечисляющим все неверные переменные (имя, ожидаемое значение, полученное значение; значения секретов маскируются).
3. Конфиг регистрируется как провайдер NestJS (`CONFIG` токен), остальные модули получают его через DI; прямые обращения к `process.env` удаляются построчно, без попутного рефакторинга логики.
4. Список переменных в README и `.env.example` генерируется или проверяется тестом: тест сравнивает ключи схемы с `.env.example` и падает, если переменная не задокументирована.
5. Значения по умолчанию остаются прежними, поведение без `.env` не меняется.

## Критерии приёмки
- Юнит-тесты `loadConfig`: значения по умолчанию, неверный enum, нечисловой порт, несколько ошибок в одном сообщении, маскирование секретов.
- Тест синхронизации схемы и `.env.example`.
- `grep -rn "process.env" apps/backend/src` находит только модуль конфигурации.
