# Issue 019: Состояние поиска не сохраняется: нет ссылки на запрос, истории и отмены устаревших запросов

**Метки:** frontend, ux

## Проблема
Найдено чтением `SearchPanel.tsx`, `App.tsx`; интерфейс вживую не запускался.
- Запрос и результат живут в `useState`/`useMutation`. Обновление страницы стирает и вопрос, и результат; поделиться ссылкой на найденный ответ нельзя.
- Поиск оформлен как `useMutation`, а не `useQuery`: нет кеша по ключу запроса (повтор того же вопроса снова ходит на сервер и снова считает эмбеддинг), нет автоматической отмены. Если пользователь отправил два вопроса подряд, ответ на первый может прийти позже и перетереть второй (в `useMutation` побеждает последний завершившийся).
- Нет истории запросов; для рабочего инструмента, где вопросы повторяются, это лишний ввод.
- Фронтенд — только на английском, хотя продукт заявлен как RU+EN. Это отдельный большой вопрос и в этот Issue не входит, но он помечен как открытый (см. «Допущения»).

## Предложение
- Хранить текущий запрос в URL (`?q=`), не добавляя роутер: `URLSearchParams` + `history.pushState` / `popstate` (≈30 строк, без новых зависимостей). При загрузке страницы с `?q=` поиск запускается автоматически.
- Перевести поиск на `useQuery({ queryKey: ['search', q], queryFn: ({ signal }) => api.search(q, signal), enabled: q !== '', staleTime: 60_000 })`: кеш и отмена через `AbortSignal` (клиент `api.search` принимает `signal`; согласовано с Issue 004). Отправка формы обновляет `q`.
- История: последние 10 запросов в `localStorage` (под выпадающим списком/чипами под полем), с кнопкой очистки. Хранить только текст запросов, только локально; предупредить в README, что на общем компьютере история видна.
- Совместимость с будущим стримом (`IMPROVEMENTS.md` п. 5): при потоковом ответе `useQuery` заменяется хуком над `EventSource`/`fetch`-стримом, но `?q=` и история остаются тем же слоем. Поэтому слой URL/истории нужно выделить в хук `useSearchQuery` отдельно от способа получения данных.

## Критерии приёмки
- Юнит-тест хука (jsdom, `@testing-library/react` уже может быть доступна — проверить; иначе чистая функция разбора/записи URL с тестом): `?q=foo` → запрос `foo`; пустой запрос не пишет в историю; история не растёт выше 10 и не содержит дубликатов.
- Cypress-сценарий: поиск → перезагрузка страницы → результат тот же; «Назад» возвращает прошлый запрос.
- Быстрые два запроса подряд показывают результат второго.

## Контракт
`/api` не меняется. Только фронтенд.

## Допущения
