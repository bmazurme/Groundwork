# Issue 035: Объяснимость поиска: компоненты оценки и отладочный режим

**Метки:** search, observability, evals

## Проблема
`SearchSource` содержит только итоговый `score` (сумма RRF) и `matchType`. Это не позволяет ответить на вопросы, без которых нельзя настраивать поиск:
- Почему фрагмент оказался на 3-м месте: ранг в keyword-ветке, ранг в vector-ветке, расстояние?
- Порог `SEMANTIC_ONLY_MAX_DISTANCE = 0.72` в `search.service.ts` подобран на одном запросе (так сказано в комментарии к константе), а само расстояние наружу не отдаётся: его нельзя посмотреть ни в интерфейсе, ни в логах, ни в eval-харнессе.
- Значения RRF лежат в узком диапазоне (максимум около 0.033 при `RRF_K = 60`), поэтому число `score` в интерфейсе ничего не говорит пользователю и выглядит как «качество».
- Для будущего реранкера (`IMPROVEMENTS.md` п. 5) нужно сравнивать порядок до и после него.

## Предложение
1. В `search.types.ts` добавить необязательное поле `debug?: { keywordRank: number | null; vectorRank: number | null; distance: number | null; rerankScore?: number }` в `SearchSource`. Поле заполняется только при `GET /api/search?debug=1`; без параметра ответ побайтно прежний, контракт совместим.
2. Вынести `reciprocalRankFusion` в отдельный файл (совпадает с `IMPROVEMENTS.md` п. 2) и возвращать из него ранги по веткам; расстояние уже есть в `distanceById`.
3. Порог `SEMANTIC_ONLY_MAX_DISTANCE` читать из env (через конфигурацию из Issue 034), значение по умолчанию 0.72 не менять.
4. Фронтенд: переключатель «Показать детали» в `SearchPanel` (сохраняется в `localStorage`), показывающий ранги и расстояние маленьким текстом в карточке источника; основное число `score` не заменять без отдельного решения владельца.
5. Структурированный лог одной строкой на запрос (`query_length`, число кандидатов по веткам, сколько отсеяно порогом) без текста запроса, чтобы не логировать содержимое пользовательских вопросов (согласуется с Issue 012 и 017).

## Критерии приёмки
- Юнит-тест RRF: ранги по веткам, `matchType`, стабильный порядок при равных оценках.
- Тест контракта: без `debug` в ответе нет поля `debug`; с `debug=1` поля заполнены, `distance` равен `null` для keyword-only результатов.
- Скриншот или описание панели деталей в PR.

## Связь
`IMPROVEMENTS.md` п. 1, 2, 5; Issue 005, 012, 021, 034. Данные из этого режима используются при подборе порога на eval-наборе.
